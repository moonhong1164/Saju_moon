PDF DELIVERY

도메인 없이 본인 메일로 테스트하기

먼저 알아둘 점

현재 서버와 무료 DB는 그대로 사용합니다. 이메일은 Resend 계정을 연결해야 실제로 발송됩니다. 별도 도메인이 없는 경우 Resend의 기본 테스트 발신 주소를 사용해 Resend 가입 이메일 한 주소로만 보낼 수 있습니다.

다른 고객들의 주소로 보내려면 나중에 본인 소유 발신 도메인을 인증해야 합니다. 아래 설정만으로 다른 사람의 이메일에 보낼 수 있는 것은 아닙니다. Resend 요금제와 발송 한도는 계정 화면에서 확인하세요.

1. Resend 무료 계정 만들기

  1. Resend 가입 화면에서 계정을 만듭니다.
  2. 본인이 실제로 받을 수 있는 이메일로 가입하고 인증을 완료합니다.
  3. 요금제 화면에서 무료 범위를 확인합니다. 테스트를 위해 도메인을 구매하거나 유료 요금제를 선택할 필요는 없습니다.

2. 발송용 API 키 만들기

Resend의 API Keys → Create API Key에서 발송 권한이 있는 키를 만듭니다. 이름은 sajumoon처럼 알아보기 쉽게 정하세요.

키는 Render 보안 환경변수에만 입력합니다. 채팅, GitHub, 화면 캡처에 키를 넣지 마세요. 관리자 화면에 키를 직접 입력하거나 저장하는 기능은 제공하지 않습니다.

3. Render 환경변수 등록하기

Render의 sajumoon-server → Environment에서 다음 네 항목을 추가합니다. 기존 DATABASE_URL, ADMIN_SETUP_TOKEN, ORDER_DATA_SECRET은 그대로 유지합니다.

이름값
EMAIL_DELIVERY_MODEowner_test
RESEND_API_KEYResend에서 만든 실제 API 키
TEST_EMAIL_TOResend 가입 및 인증을 완료한 본인 이메일
MAIL_FROM사주문 <onboarding@resend.dev>

저장 후 새 배포가 Live가 될 때까지 기다립니다. FREE_TRIAL_MODE=true와 SALES_ENABLED=false는 그대로 두므로 실제 카드 결제나 유료 AI를 켤 필요가 없습니다.

4. 실제 수신 확인하기

  1. 관리자 메뉴의 이메일에서 설정이 등록되었는지 확인합니다. 이는 아직 수신 성공을 의미하지 않습니다.
  2. 새 테스트 주문에 TEST_EMAIL_TO와 같은 본인 이메일을 입력하면 PDF를 만든 뒤 자동 발송을 요청합니다.
  3. 기존 PDF를 보내려면 주문 상세의 PDF 이메일로 보내기를 누릅니다. 주문의 이메일이 본인 테스트 주소와 같아야 합니다.
  4. Resend의 발송 기록, 본인의 받은편지함과 스팸함을 확인합니다.

기존 다운로드 전용 주문은 설정 변경만으로 자동 발송하지 않습니다. 관리자가 명시적으로 요청하거나 새 이메일 주문을 생성해야 합니다. 테스트 주소가 다른 기존 주문을 다른 이메일로 임의 전달하지 않습니다.

발송에 실패하면

  • API 키·권한 오류: Render에 올바른 발송 키가 있는지 확인합니다.
  • 인증·수신 주소 오류: 가입 이메일과 TEST_EMAIL_TO, 기본 발신 주소를 확인합니다. 도메인 없는 테스트에서는 다른 이메일로 보낼 수 없습니다.
  • 한도·속도 제한: Resend의 무료 발송 사용량과 안내를 확인합니다.

설정·인증 오류는 무작정 자동 재시도하지 않고 운영자 확인 상태로 표시합니다. 일시적인 오류는 기존 작업 대기열에서 재시도합니다. 메일 요청 접수와 받은편지함 도착은 다르며, 실패하더라도 준비된 PDF는 다운로드할 수 있습니다.

키·이메일 계정이 없는 현재 개발 환경에서는 실제 발송을 하지 않았습니다. 설정 후 본인 수신까지 확인해야 연결 검증이 완료됩니다.
