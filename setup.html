현재 사이트와 서버는 별도입니다

GitHub Pages 주소에서는 무료 사주와 PDF 샘플 같은 화면을 볼 수 있습니다. 관리자 로그인·주문·결제·메일은 Node 서버가 실행되는 주소에서 사용할 수 있습니다. GitHub에 파일을 올리는 것만으로 서버가 배포되지는 않습니다.

1. 서버 배포하기

  1. Railway에 가입·로그인하고 GitHub 저장소를 연결합니다. 호스팅 요금은 서비스의 현재 가격을 확인하세요.
  2. 저장소 moonhong1164/Saju_moon, 배포 브랜치 gh-pages를 선택합니다. 저장소의 Dockerfile로 빌드합니다.
  3. 영구 볼륨을 만들고 /data에 연결합니다. 볼륨이 없으면 재배포 후 계정·주문이 사라질 수 있습니다. 컨테이너 사용자에게 볼륨 쓰기 권한을 설정합니다.
  4. 서비스 설정에서 공개 도메인을 생성합니다. 관리자 페이지도 이 서버 도메인에서 엽니다.

Railway는 가능한 호스팅 예시이며 계정·결제·배포를 자동으로 실행하지 않습니다. 다른 Docker/Node 호스트도 사용할 수 있습니다.

2. 서버 보안 설정 입력하기

관리자 로그인부터 확인할 때는 아래 설정으로 시작하세요. 실제 키와 비밀번호는 채팅이나 GitHub에 올리지 않습니다.

항목값
NODE_ENVproduction
DATA_DIR/data
PUBLIC_BASE_URL방금 만든 서버의 실제 https 주소
SALES_ENABLEDfalse (결제는 아직 열지 않음)
ADMIN_SETUP_TOKEN무작위 32자 이상의 초기 설정 키
ORDER_DATA_KEY무작위 32바이트를 Base64로 인코딩한 암호화 키

호스팅 서비스의 보안 키 생성 기능이나 신뢰할 수 있는 비밀번호 관리자를 이용하세요. ORDER_DATA_KEY는 계정 비밀번호가 아니며 DB와 따로 안전하게 보관해야 합니다.

3. 첫 계정 만들고 로그인하기

  1. 배포된 서버 주소 끝에 /admin.html을 붙여 접속합니다.
  2. 첫 계정 생성 화면에서 ADMIN_SETUP_TOKEN과 원하는 아이디·비밀번호를 입력합니다. 비밀번호는 12자 이상으로 설정합니다.
  3. 계정은 한 번만 만들 수 있습니다. 생성 후에는 아이디·비밀번호로 로그인합니다.
  4. 계정 메뉴에서 비밀번호를 바꿀 수 있고, 상단의 로그아웃으로 로그인을 종료할 수 있습니다. 로그인은 최대 8시간 유지됩니다.

사이트 전체를 같은 서버 주소로 운영하면 무료 화면과 관리자 메뉴를 자연스럽게 함께 사용할 수 있습니다. GitHub Pages를 계속 쓸 경우 관리자 링크를 실제 서버의 관리자 주소로 변경해야 합니다.

4. 결제·메일은 그다음에 연결합니다

관리자 로그인은 결제사 키가 없어도 먼저 확인할 수 있습니다. 유료 판매를 열 때 토스 심사·서버 키, Resend 발신 도메인, 실제 판매자 정보와 정책을 준비합니다. AI를 쓸 경우 AI 계정과 모델도 별도로 설정합니다.

현재 제공한 코드는 로컬 테스트를 통과했지만, 실제 호스팅 계정에 서버를 배포한 상태는 아닙니다.
